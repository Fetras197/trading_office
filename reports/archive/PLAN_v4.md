# PLAN — Офис v4: облачный режим (GitHub Actions), мягкий вход, «Почему не вошли»

Причина «0 сделок за неделю» (по office.db/board.db): из 406 прогонов 116 — `trader: hold`, 32 — short-circuit «нет мнения ≥0.5», десятки — запреты «Картины дня»/событий,
ещё отказы шины («ссылка на отчёт»). Цепочка bull/bear/trader/risk/PM/executor на `claude -p` имеет 8 LLM-вето подряд. Телефон при этом работает 24/7 и садит батарею.

## 1. Облако (GitHub Actions)
- `.github/workflows/office.yml`: cron `*/20 * * * *` + `workflow_dispatch`; `concurrency: office` (без параллельных прогонов); один прогон = `python -m office cloud`.
- Состояние (office.db, board.db, gemini_budget.json, data_cache) — в отдельной ветке `state` репозитория (checkout в `state/`, после прогона commit+push; при гонке — rebase/retry).
  Ветка `state` создаётся/засевается текущими БД с телефона. Артефакты/кэш не используем: кэш Actions вытесняется, ветка — надёжна и видна.
- Секреты: `ALPACA_API_KEY`, `ALPACA_SECRET_KEY`, `GEMINI_API_KEY`, `TG_TOKEN`, `TG_CHAT`. Ключи в репозиторий не попадают (.env в .gitignore; вывод маскируется).
- `config.STATE_DIR` (env `TO_STATE`): пути БД/бюджета/кэша; по умолчанию корень проекта (телефонный режим совместим).
- `office/cloud.py`: один проход = restore → watch (сверка с брокером) → scheduler.run_due (исследовательский отдел, отчёты) → screen → cycle (зал) → «Почему не вошли» → save.
  Отбрасываем: tgbot (опрос команд), IT-отдел/батарея, лабораторию (vectorbt), labtrial, weights-предложения («да» из чата невозможно).
- Расписание Minsk: утренний 08:00, вечерний 21:00 (с блоком «Почему не вошли»), воскресный 20:00 — как раньше, через Scheduler (catch-up окна ≥ интервала cron).

## 2. Без Claude
- Удаляем `ClaudeBackend`, `DebateLLM`, зависимость tradingagents, `claude -p`, fallback аналитиков на Claude. Все роли → `GeminiBackend` (3 модели по очереди).
- Дневной бюджет Gemini (env `GEMINI_DAILY_BUDGET`, по умолчанию 450 запросов/сутки UTC; hall ≥70%, фон 25%, мелочь 5%) остаётся; исчерпан → роли abstain/механический запасной путь.
- Экономия запросов: аналитики зала запускаются ТОЛЬКО для активов с техническим сигналом (код) и для открытых позиций не нужны вовсе; кэш ответов 1,5 ч.

## 3. Мягкий вход (лимиты риска НЕ меняются: 2%/сделку, −5%/день, ≤5 входов/день, ≤3 позиции, без плеча и шортов — только RiskGate)
- Решение в коде (`office/entry.py`): вход, если (а) технический сигнал по 1h-индикаторам (тренд ИЛИ отскок от перепроданности), (б) среди живых аналитиков «за» ≥ половины и «за» > «против».
- Неполные данные (нет новостей/фундаментала, <3 живых голосов, сбой источника) → size_mult 0,5, а не пропуск. Нет ни одного голоса (Gemini недоступен) → не входим.
- Стоп = 1,5·ATR, тейк = 3·ATR (R:R 2), частичная фиксация/безубыток — как раньше (manage.py). Режим «паника» и события High ±30 мин блокируют вход (это защита, не вето LLM). «Картина дня» больше не вето.
- Цель 1–3 сделки/сутки; пороги — константы в entry.py, подбираются по отчёту.

## 4. «Почему не вошли»
- Таблица `nogo` в journal: каждый оцененный кандидат → стадия блокировки + причина + близость к входу (score). Вечером — топ-3 ближайших за сутки: «ASSET — заблокировал: …».

## 5. Новости и макро
- Новости: цепочка источников (Alpaca News API → Google RSS → Bing RSS → Yahoo Finance RSS; крипта + CoinDesk/Cointelegraph RSS), дедуп, время публикации.
- Макро: Yahoo → FRED CSV (VIXCLS, DGS10/5/3MO, SP500, DTWEXBGS, DCOILWTICO) как запасной; BLS v1 → FRED (CPIAUCNSL, UNRATE); Fear&Greed (alternative.me) → CoinGecko global fallback отсутствует — остаётся запас по кэшу.
- Свечи акций: Yahoo → бары Alpaca IEX (Yahoo часто режет IP облаков). Крипто: Binance → Alpaca bars (уже есть).

## 6. Универсум
- Исключить ONDO, USDC (и прочие стейблы USDT/DAI/PYUSD…); фильтр по обороту: крипто ≥ $2M/сутки по барам (close·volume), акции ≥ $20M/сутки; считается в screener по дневным барам.

## Тесты / приёмка
- pytest: entry (мажоритарность, половинный размер, нет голосов), nogo/ежевечерний блок, фильтры универсума, fallback-источники (моки), llm без Claude, cloud pass на фейках, лимиты RiskGate неизменны.
- Прогон в Actions: `workflow_dispatch`, ссылка на run; в Telegram приходит стартовое сообщение.
- Риски: Binance/Yahoo блокируют IP GitHub (→ Alpaca-фоллбеки); лимиты Gemini free tier; гонка push в `state` (concurrency + retry); рассинхрон с телефонным офисом (его нужно остановить: `./office.sh stop` в Termux + убрать watchdog из crontab).

## Итог второго мнения Gemini (gemini-plan)
- ПРИНЯТО: `board.db` = 132 МБ (188k строк strategies лаборатории) > лимита файла GitHub → в облако идёт урезанная копия (без strategies, отчёты ≤14 дней, VACUUM); ветка `state` перезаписывается одним коммитом (force-push, история не копится); SQLite не мержится — один писатель (concurrency), rebase не используем.
- ПРИНЯТО: гонка/дубли ордеров — перед покупкой сверка с брокером (позиция/открытый ордер по символу); при сбое сохранения состояния следующий прогон всё равно берёт позиции у Alpaca (`watch`).
- ПРИНЯТО: стоп-кран с телефона — repository variable `OFFICE_HALT=1` (GitHub mobile) → прогон только сопровождает позиции, новых входов нет; плюс отключение workflow.
- ПРИНЯТО: две копии офиса на одном счёте — в Termux выполнить `./office.sh stop` (`.user_stopped` уже стоит), в облаке — проверка, что брокерские позиции есть в журнале (orphans → сообщение).
- ОТКЛОНЕНО: Redis/Supabase (лишний сервис и ключи при той же задаче); возврат Claude «как вето» (прямое требование убрать claude -p); «RPM 429» — уже есть глобальный интервал 4 с + семафор 3 + backoff по моделям.
- УЧТЕНО: блокировка IP облака — у каждого источника свечей/новостей/макро есть запасной (Alpaca bars/news, FRED); фактическую доступность покажет первый прогон.
